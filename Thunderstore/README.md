## 1.19.1 更新（历史）

**多人共享修好了，这正是 1.19.0 弄坏的东西。** 1.19.0 规定：没有证据证明对方装了本模组，就连招呼都不发，只认"被 `AllowlistedPeers` 点名"或"对方先发包"。两边都遵守同一条规则，就互相等死——现场两份日志都写着 `not one packet heard from any of them`（主机和客机各一行），于是局内只看得到自己，结算只剩自己那一部分。

现在默认**与名册内每个玩家共享**，走 GTFO-API 的 free-sized 网络事件（StatDisplay、AccuracyTracker 等模组在用的同一条通道，字节自带 key、magic 与版本签名，没装模组的机器不会触发任何 handler，直接丢弃）。没装这个库的机器自动回落游戏自带字节通道；某台对端到底走哪条，由它第一次回包决定，未确定前两条都发，所以混合安装的房间也能配对。客机之间也会直接互发各自的行，不再依赖主机能否观测到你。

想回到旧规则：`[Squad Sync] ShareWithEveryPlayer` 设为 `false`，此时仍按 `[Squad Sync] AllowlistedPeers` 点名（填大厅里那串 SteamID64）或等对方先开口。两个键都支持游戏中热改。

**失血量按玩家水位线计量。** 旧实现只在伤害方法前后各读一次血量，主机看不到别人血量因复制更新下降的那部分，于是「阵亡 / 失血」出现 `—` 或偏小。现在每次观测都记录绝对血量与该次上限：只有「上限未变且血量下降」才计入，同一数值重复上报不重复计，回复/复活只抬高水位，上限升降（感染、上限修正）只重新定基；补丁面覆盖 `ReceiveSetHealth`（主客机之间真正传血的通道）、`OnRevive`、`OnApplyDamageOverTimeModifier`、`OnKilledByTankTentacle`，并在 `Setup` 时播种。工具效率里的扫描数字随行共享，同步恢复后一并恢复。

**结算表格按测量拟合，不再用倍数猜。** 以真实测得的表格尺寸二分逼近，直到填满「完成度区块底边到返回大厅按钮上沿」这段条带的 92%–96%，或触到页面宽度、或达到局内字号的 3.5 倍；再把余宽平均分给右侧数值列，第 2–5 列仍等宽取最宽。2560×1440 成功页上从约 600×370 变成约 1960×880 并铺满 2512 宽。隐藏 / 透明度为 0 / 排到窗口外的幽灵按钮照旧排除，不会挡住表格。

**`说明` 行现在也能自定义，和 `评价` 一样写在 `scoring.json` 里。** `Reasons` 每句结算说明一个模板，数字用占位符引用：`{damage}`、`{share}`、`{count}`、`{kills}`、`{deaths}`、`{uses}`、`{firstMarks}`、`{weakspots}`、`{hits}`、`{shots}`、`{efficiency}`（每个键只接受自己那行真正有的占位符，写错了整份文件判为无效并保留上次有效配置）。留出厂模板即跟随语言设置；改成空串则该行不显示说明。改完 `scoring.json` 局内外都会即时生效。

**协议仍是 v8**，但 1.19.0 不发包：需要互看统计的队友都要升到 **1.19.1**。

## 1.19.0 更新（历史）

**伤害改取游戏实际结算值。** 旧实现取的是武器携带的原始伤害，游戏在之后才乘上「被击部位护甲」与「精准命中（弱点）倍率」，所以打弱点与打身体被记成同一个数。现在改为在游戏应用伤害前后读敌人的实际血量差，子弹、近战、爆炸与 EWC 的延迟弹丸 / 破片 / DOT 走同一条接收口径。

**沉睡击杀只在近战与触手两行计权。** 两行各自一个倍率（`SleepingMeleeKillMultiplier` / `SleepingScoutKillMultiplier`，默认 2，范围 1–10）；小怪 / 精英 / BOSS 三档只统计总数、不再吃睡眠倍率。旧字段 `SleepingKillMultiplier` 保留为这两项缺失时的回退来源。

**结算单元格统一格式。** 唯一分隔符 ` / `，单位与含义移到行名，`%`、`~`、`—` 保留；结算第 2–5 列等宽，取其中最宽者。近战与触手两行是三列：总击杀 / 沉睡击杀 / 伤害（触手伤害现在随同步传输）。

## 局内 HUD

`F8` 显示 / 隐藏。默认列：

`玩家 | 伤害 占比 | 友伤 | 命中率 | 弱点率 | 总弹丸 命中 弱点`

伤害只含敌伤；占比按已观测队伍敌伤计算。`~` 表示估算或分母只覆盖已获得的数据；无观测显示 `—`。不按伤害反推命中或弱点。武器行占比使用该武器敌伤；玩家总伤可包含工具，因此两把枪占比之和不一定等于玩家总占比。

## 局外结算

成功 / 失败均显示固定布局的影响力矩阵，按综合评分降序排列。保留原表格行与布局，**工具动作和工具统计只在结算显示**。

十三项指标：总伤害、硬直、击杀、救援、弱点率、命中率、补给效率、工具效率、独存、倒地、友伤、近战击杀、Scout 击杀。击杀可分小怪 / 精英 / BOSS，基础价值分别 **0.5 / 1 / 1.5**。分档称号只分解同一击杀评分，不重复加分。

- 炮台：发射、有效命中和工具敌伤。
- 绊雷：工具部署、回收、触发及工具敌伤。消耗品野雷只归部署者总伤，不加入工具部署 / 触发或当前工具行。
- 胶枪：真实弹丸发射、命中和胶住敌人等已有统计。
- 扫描：使用与确认标记；候选可标记列表不是成功扫描。机器人窗口计次仍保留估算标记。
- 近战只认近战伤害，Push 不算；Scout 使用原生 Scout 身份。
- 沉睡是致死前明确观察的状态；无法判定保留未知，未知无额外加成，不冒充清醒或沉睡。
- 本人补给次数归实际受益者，不是拿包操作的人；全满且没有实际收益不计。给别人补给仍按原效率语义统计。
- 失血只累计伤害回调中的实际生命损失，治疗不抵扣；上限变化本身不算失血。原生回调覆盖仍需实机确认。

## JSON 配置

评分配置位于插件旁的 `CombatPanel-config/scoring.json`。修改已有文件对应字段；插件不覆盖已有手改配置，无效内容保留上次有效值。缺失字段使用默认值。

```json
{
  "SleepingKillMultiplier": 2.0,
  "Titles": {
    "Damage": { "Title": "火力核心", "Description": "总伤害突出领先" },
    "MinorKills": { "Title": "杂兵清道夫", "Description": "小怪击杀贡献领先" },
    "EliteKills": { "Title": "精英猎手", "Description": "精英击杀贡献领先" },
    "BossKills": { "Title": "首领终结者", "Description": "BOSS 击杀贡献领先" },
    "TeamPillar": { "Title": "平平无奇", "Description": "没有突出领先的有效项目" }
  }
}
```

称号最多 16 字符，描述最多 96 字符；保留默认文字时随语言设置切换。`ZeroScore` 为旧配置保留项，本版不会绕过 top 规则强制授予零分称号。

分配顺序：总评分降序；同分按稳定玩家身份顺序。只取启用、权重非零、有有效数据且独占 top 的项目。并列 / 全零不产生领先；倒地和友伤要求真实负面最严重。按正向 / 负向实际贡献绝对值选最大候选；重复称号由排序靠前者先得，其余尝试下一候选，无候选为中性称号。

默认权重：`TotalDamage .95, Stagger 1.40, Kills .70, Revives .28, WeakspotRate .44, Accuracy .28, SupplyEfficiency .78, ToolEfficiency .80, LoneSurvivor 1.60, Downs .55, FriendlyFire .75, MeleeKills .55, ScoutKills .60`。评分限制在 0–100；无数据、失败独存、禁用项目不制造有效贡献。工具效率的评分来源仍为扫描首次标记，其他工具统计只是显示，不暗中增加权重。

## 多人和兼容

每台机器独立评分，不将本地权重强加给队友。快照传输观测数据，主机负责其可测的伤害，玩家本人提供其本机命中、补给和扫描。没有数据来源的字段仍可能为空；主机没装模组时，装模组客机之间只共享可观测子集，`~` 不表示完整全队实测。

EWC 是可选集成，**不是强依赖**。公共 DLL 始终带无程序集强引用的运行时弹丸桥接；无 EWC 也可加载。接口契约按已检查的 EWC 版本验证，不保证任意第三方改版行为。普通射线与延迟弹丸分别去重，真实命中部位用于弱点判断。

结算可写 JSON 存档，Rundown 和关卡分开记录。更多实现和构建说明见 [源码仓库](https://github.com/hawchou1995/GTFOCombatPanel)。
