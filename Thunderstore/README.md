# CombatPanel

独立 GTFO 战斗统计面板：局内查看战斗数据，成功或失败结算查看队伍贡献。仅依赖 **BepInEx-BepInExPack_GTFO-3.2.4**；EWC（ExtraWeaponCustomization）是可选集成，不是依赖。

**源码 / Source：[GitHub — hawchou1995/GTFOCombatPanel](https://github.com/hawchou1995/GTFOCombatPanel)**

## 安装

- **r2modman / Thunderstore Mod Manager**：搜索 `CombatPanel` 安装到 GTFO profile，BepInEx 依赖会自动带上。需要共享统计的每台机器装同一版本。
- **手动安装**：先把 BepInEx 装进 GTFO 目录，再把包内 `BepInEx/plugins/GTFOCombatPanel/` 整个目录原样放进同一路径。
- `CombatPanel-config/scoring.json` 只在缺失时写入一次；你手改过的配置不会被覆盖，写错的内容整份判为无效并保留上次有效值。
- `F8` 在关卡内显示 / 隐藏 HUD 表。**在结算页上它是「强制出板」**：按一次立即用兜底条带把评分板画出来（不等标题、完成区、页脚或交互证明就绪，也不受三个可见性开关限制），再按一次交回自动判定。
- 多人：快照协议为 **v8**，与旧协议明确不兼容（旧协议包会被拒收，不是"勉强可用"）。

## 局内 HUD

`F8` 显示 / 隐藏。默认列：

`玩家 | 伤害 占比 | 友伤 | 命中率 | 弱点率 | 总弹丸 命中 弱点`

伤害只含敌伤；占比按已观测队伍敌伤计算。`~` 表示估算或分母只覆盖已获得的数据；无观测显示 `—`。不按伤害反推命中或弱点。武器行占比使用该武器敌伤；玩家总伤可包含工具，因此两把枪占比之和不一定等于玩家总占比。

## 局外结算

成功 / 失败均显示固定布局的影响力矩阵，按综合评分降序排列。保留原表格行与布局，**工具动作和工具统计只在结算显示**。

十三项指标：总伤害、硬直、击杀、救援、弱点率、命中率、补给效率、工具效率、独存、倒地、友伤、近战击杀、Scout 击杀。击杀可分小怪 / 精英 / BOSS，基础价值分别 **0.5 / 1 / 1.5**。分档称号只分解同一击杀评分，不重复加分。

- 炮台：发射、有效命中和工具敌伤。
- 绊雷：工具部署、回收、触发及工具敌伤。消耗品野雷只归部署者总伤，不加入工具部署 / 触发或当前工具行。
- 胶枪：真实弹丸发射、命中和胶住敌人等已有统计。
- 扫描：使用与确认标记；候选可标记列表不是成功扫描。机器人窗口计次仍保留估算标记。
- 近战只认近战伤害，Push 不算；Scout 使用原生 Scout 身份。
- 沉睡是致死前明确观察的状态；无法判定保留未知，未知无额外加成，不冒充清醒或沉睡。
- 本人补给次数归实际受益者，不是拿包操作的人；全满且没有实际收益不计。给别人补给仍按原效率语义统计。
- 失血只累计伤害回调中的实际生命损失，治疗不抵扣；上限变化本身不算失血。

## 结算板的落位与字号

两个结算页的板子都**优先从页面自己量得到的上下边界落位**，量不到时改用兜底条带，**不会空屏**：

- 严格条带的前提是页面自己的动画已经结束：失败页要求原生 `任务失败` 标题**文字已经完整显示**（它的透明度乘以上层所有 CanvasGroup，达到满不透明）**并且**实测底边连续两次读数一致；成功页要求「已清理分区」图标行与完成区块的实测边稳定。文字还在淡入、只有矩形不动，不算就绪——那正是「标题字样还没渲染完就出评分面板」这一现象的来源。
- 上下边界是写死的一条带：**上边界**取「已清理分区」图标行（含该行标签）的实测底边加净空（1080p 16 px，按窗口高度等比缩放）；**下边界**取本机真正能看到的页脚——主机是「返回大厅 / 送所有囚犯回大厅」按钮上沿，客机是「正在等待…」文字块上沿——再减同一净空。板子自上边界向下顶对齐铺开，**不是居中**，所以带越高表越大、字号越大。
- **真实锚点拿不到时，用「屏幕安全区」兜底出板，绝不空屏**：兜底同样只用上面那两条边；两边都量不到时才退到窗口安全区，并且仍然避开扫描到的任何原生控件。兜底板逐帧重测，遇到遮挡是**位移或降低不透明度**，不是消失。一旦页面的真实锚点稳定可测，板子自动回到严格条带，不需要 `F8` 关开。
- 带太高或太矮都不会压到上方：带高决定行高与字号（带不够时缩字号、收行距）；板子比带还高时保持上边界不动、**越过下沿时按 0.55 变淡绘制，绝不压上方图标行**。
- 字号由这段条带按固定行数搜索得到（到条带 92%–96% 或页面可用宽度即停，最高为局内字号的 3.5 倍）；带太矮时按带高给出更小的字号，可读下限只是偏好——带不够时宁可缩小字号，也不把板子画到边界之外。板子落位后不会因为一两帧的抖动移动；**页面本身在落位后又明显移动或改变尺寸时（别的模组重排页脚、分辨率变化等），板子会自动重新测量并按新条带重新拟合**。
- 结算页仍在持续收快照：数据让表格变大时，会先按落位时真正用到的条带与该帧按钮净空校验，装不下就保留已上板的网格，绝不压按钮或标题。

鼠标滚轮在板子上可缩放字号（`F8` 强制出板时同样有效），两个结算页各存一份（`[Results] SuccessFontScale` / `FailureFontScale`，见下）。缩放只乘在页面自己量出的字号上，往上最多夹回该字号，因此不会盖住按钮。

## JSON 配置

评分配置位于插件旁的 `CombatPanel-config/scoring.json`。修改已有文件对应字段；插件不覆盖已有手改配置，无效内容保留上次有效值。缺失字段使用默认值。

```json
{
  "SleepingKillMultiplier": 2.0,
  "Titles": {
    "Damage": { "Title": "火力核心", "Description": "总伤害突出领先" },
    "MinorKills": { "Title": "杂兵清道夫", "Description": "小怪击杀贡献领先" },
    "EliteKills": { "Title": "精英猎手", "Description": "精英击杀贡献领先" },
    "BossKills": { "Title": "首领终结者", "Description": "BOSS 击杀贡献领先" },
    "TeamPillar": { "Title": "平平无奇", "Description": "没有突出领先的有效项目" }
  }
}
```

称号最多 16 字符，描述最多 96 字符；保留默认文字时随语言设置切换。`ZeroScore` 为旧配置保留项，本版不会绕过 top 规则强制授予零分称号。滚轮字号偏好写在 BepInEx 自己的 `.cfg`（`[Results] SuccessFontScale` / `FailureFontScale`，默认 1.0，范围 0.5–2.0）。

分配顺序：总评分降序；同分按稳定玩家身份顺序。只取启用、权重非零、有有效数据且独占 top 的项目。并列 / 全零不产生领先；倒地和友伤要求真实负面最严重。按正向 / 负向实际贡献绝对值选最大候选；重复称号由排序靠前者先得，其余尝试下一候选，无候选为中性称号。

默认权重：`TotalDamage .95, Stagger 1.40, Kills .70, Revives .28, WeakspotRate .44, Accuracy .28, SupplyEfficiency .78, ToolEfficiency .80, LoneSurvivor 1.60, Downs .55, FriendlyFire .75, MeleeKills .55, ScoutKills .60`。评分限制在 0–100；无数据、失败独存、禁用项目不制造有效贡献。工具效率的评分来源仍为扫描首次标记，其他工具统计只是显示，不暗中增加权重。

## 多人和兼容

每台机器独立评分，不将本地权重强加给队友。快照传输观测数据，主机负责其可测的伤害，玩家本人提供其本机命中、补给和扫描。没有数据来源的字段仍可能为空；主机没装模组时，装模组客机之间只共享可观测子集，`~` 不表示完整全队实测。

EWC 是可选集成，**不是强依赖**。公共 DLL 始终带无程序集强引用的运行时弹丸桥接；无 EWC 也可加载。接口契约按已检查的 EWC 版本验证，不保证任意第三方改版行为。普通射线与延迟弹丸分别去重，真实命中部位用于弱点判断。

结算可写 JSON 存档，Rundown 和关卡分开记录。更多实现和构建说明见 [源码仓库](https://github.com/hawchou1995/GTFOCombatPanel)。

## 验证边界

本模组的结论分两类，不混用：**编译与托管重放断言**（`scripts/Verify.ps1` 对真实 BepInEx / Interop 程序集构建并跑无 Unity 的策略与场景重放，可复现）；**实机观察**（截图、日志、手感，只在明确记录时才算证据）。断言覆盖不到 Unity 原生回调时序、页面动画的实际轨迹和玩家屏幕前的观感，这类结论一律需要实机复核才能成立。逐版的验证记录与未验证项写在包内 `CHANGELOG.md`。
