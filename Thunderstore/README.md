## 1.18.0 更新

- 修复可复现的击杀时序、雷归属与重置、炮台发射去重、胶枪弹丸池复用、扫描确认和快照分母问题。无法确定归属或状态时不编造数据。

**验证边界：本轮不做实机测试。** 自动化覆盖托管生产逻辑、同步场景、配置及双 profile 编译，不等于 Unity 原生回调、Steam 多人或渲染验证。重连“异世界”的现有日志不足以证明或排除本模组因果，未宣称解决。

## 局内 HUD

`F8` 显示 / 隐藏。默认列：

`玩家 | 伤害 占比 | 友伤 | 命中率 | 弱点率 | 总弹丸 命中 弱点`

伤害只含敌伤；占比按已观测队伍敌伤计算。`~` 表示估算或分母只覆盖已获得的数据；无观测显示 `—`。不按伤害反推命中或弱点。武器行占比使用该武器敌伤；玩家总伤可包含工具，因此两把枪占比之和不一定等于玩家总占比。

## 局外结算

成功 / 失败均显示固定布局的影响力矩阵，按综合评分降序排列。保留原表格行与布局，**工具动作和工具统计只在结算显示**。

十三项指标：总伤害、硬直、击杀、救援、弱点率、命中率、补给效率、工具效率、独存、倒地、友伤、近战击杀、Scout 击杀。击杀可分小怪 / 精英 / BOSS，基础价值分别 **0.5 / 1 / 1.5**。分档称号只分解同一击杀评分，不重复加分。

- 炮台：发射、有效命中和工具敌伤。
- 绊雷：工具部署、回收、触发及工具敌伤。消耗品野雷只归部署者总伤，不加入工具部署 / 触发或当前工具行。
- 胶枪：真实弹丸发射、命中和胶住敌人等已有统计。
- 扫描：使用与确认标记；候选可标记列表不是成功扫描。机器人窗口计次仍保留估算标记。
- 近战只认近战伤害，Push 不算；Scout 使用原生 Scout 身份。
- 沉睡是致死前明确观察的状态；无法判定保留未知，未知无额外加成，不冒充清醒或沉睡。
- 本人补给次数归实际受益者，不是拿包操作的人；全满且没有实际收益不计。给别人补给仍按原效率语义统计。
- 失血只累计伤害回调中的实际生命损失，治疗不抵扣；上限变化本身不算失血。原生回调覆盖仍需实机确认。

## JSON 配置

评分配置位于插件旁的 `CombatPanel-config/scoring.json`。修改已有文件对应字段；插件不覆盖已有手改配置，无效内容保留上次有效值。缺失字段使用默认值。

```json
{
  "SleepingKillMultiplier": 2.0,
  "Titles": {
    "Damage": { "Title": "火力核心", "Description": "总伤害突出领先" },
    "MinorKills": { "Title": "杂兵清道夫", "Description": "小怪击杀贡献领先" },
    "EliteKills": { "Title": "精英猎手", "Description": "精英击杀贡献领先" },
    "BossKills": { "Title": "首领终结者", "Description": "BOSS 击杀贡献领先" },
    "TeamPillar": { "Title": "平平无奇", "Description": "没有突出领先的有效项目" }
  }
}
```

称号最多 16 字符，描述最多 96 字符；保留默认文字时随语言设置切换。`ZeroScore` 为旧配置保留项，本版不会绕过 top 规则强制授予零分称号。

分配顺序：总评分降序；同分按稳定玩家身份顺序。只取启用、权重非零、有有效数据且独占 top 的项目。并列 / 全零不产生领先；倒地和友伤要求真实负面最严重。按正向 / 负向实际贡献绝对值选最大候选；重复称号由排序靠前者先得，其余尝试下一候选，无候选为中性称号。

默认权重：`TotalDamage .95, Stagger 1.40, Kills .70, Revives .28, WeakspotRate .44, Accuracy .28, SupplyEfficiency .78, ToolEfficiency .80, LoneSurvivor 1.60, Downs .55, FriendlyFire .75, MeleeKills .55, ScoutKills .60`。评分限制在 0–100；无数据、失败独存、禁用项目不制造有效贡献。工具效率的评分来源仍为扫描首次标记，其他工具统计只是显示，不暗中增加权重。

## 多人和兼容

每台机器独立评分，不将本地权重强加给队友。快照传输观测数据，主机负责其可测的伤害，玩家本人提供其本机命中、补给和扫描。没有数据来源的字段仍可能为空；主机没装模组时，装模组客机之间只共享可观测子集，`~` 不表示完整全队实测。

EWC 是可选集成，**不是强依赖**。公共 DLL 始终带无程序集强引用的运行时弹丸桥接；无 EWC 也可加载。接口契约按已检查的 EWC 版本验证，不保证任意第三方改版行为。普通射线与延迟弹丸分别去重，真实命中部位用于弱点判断。

结算可写 JSON 存档，Rundown 和关卡分开记录。更多实现和构建说明见 [源码仓库](https://github.com/hawchou1995/GTFOCombatPanel)。
