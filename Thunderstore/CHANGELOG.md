# Changelog

## 1.19.61

- **客机结算页的板不再压住「正在等待厅主」那行字。** 客机的失败页上，主机那边「返回大厅」按钮的位置换成了一行等待提示；以前模组量的是另一个更靠下的框，于是板盖在提示上，而且每次重画都被自己的检查判成「压住页脚」，只能按 F8 看到一帧。现在板以上面两样东西里更靠上的那一个为准——这个页面上「返回大厅」按钮自己摆放的位置，和那行提示真正画出来的字形；两样都量不到就保留原版页面、过一会儿再量，不再拿屏幕底边或别的控件凑一条边界，F8 也不会。主机页、成功页、固定布局与评分没有变。

## 1.19.60

- **局内 HUD 不会再多出两个「空白队友」。** 上一版里，如果队里有人没装本模组，你中途给他贴一个医疗包，他就会突然出现在你的局内表里：武器全是「—」、击杀全是 0、连名字都没有——因为「收到过你的补给」被当成了「有统计」。现在表里只会出现三类行：你自己、本局真的把数据发给你的队友、以及主机测到的座位（bot 也算）。谁在名单里、握手成没成功、你给他贴过几个包、数字是不是全 0、行上有没有名字，都不再决定这一行出不出现。你贴出去的包本身照旧记在对方名下，晚到的可信数据会正常合上去；真实的 0 还是 0，读不到的仍然是「—」或「?」。
- **客机结算页的表格不再「先大后小跳一下」。** 客机页原先在揭示动画还没画完时就先摆一版表（626 px 条带、12 px 字），动画停下后条带只剩 534 px，于是同一张表被重排成 10 px 字、整体下移 123 px。现在客机页要等这一页自己的揭示动画给出答复（或这一页根本没有揭示动画，且它的几何已经连续两次量到同一个值）并且下界真的是页面上量到的控件，才落第一版表——首版就是终版，不会再自动缩一次。没有加任何「帧数」「预算」或「字号上限」，主机页、固定模式、F8、滚轮、原版回退与迟到控件保护都没有变。
- **客机失败页的板不再压住「任务失败」标题。** 客机失败页的上界原来是一个固定的窗口留边（1440p 上 32 px），而同一张页面的兜底路径用的是标题实测底边（488.33 px）——同一页两个说法，严格路径那张表底对齐墙、向上生长，于是会盖住标题的下半截 40~90 px。现在两条路径都从「活着的任务失败标题底边」出发，更靠下、真实存在的交互控件仍会继续收紧，页面下沿只做封顶。代价是客机失败页的条带变短、字号随之变小，和主机页从此一致。
- **结算 JSON：每名玩家只有一个「补给效率 / 弹药包 / 工具包 / 血包」键。** 以前同一个格子会再写一遍旧的三格键（`补给效率 / 本人 / 弹药`，英文 `Supply efficiency / self / ammo`），它的第 2 格是「本人总次数」，和新格第 2 格「弹药包」不是同一个量，读文件的人无从分辨该按哪种形状解读。旧键已从新写的文件里移除，**你之前用旧键写的脚本请改读 `counters`**：总数是 `counters.selfSupplyUses`，拆分是 `counters.selfAmmoUses` / `selfToolUses` / `selfMedicalUses`，旁边还有 `selfSupplyKindsKnown` / `selfMedicalKnown` 两个「是否真的测到」的标志——和旧键引用的是同一份测量，只是以数字而不是文案给出。已经存在的旧文件不会被改写，旧键在**历史文件**里照旧在。
- **验证：** 本版只做上述定点修正，未改协议、握手、收包门、评分权重与配置。`scripts\Verify.ps1` 在本机 Survival 档案上用该档自己的 BepInEx core／IL2CPP interop 重编并跑完整回归（插件构建、ScoutHookSafety 引用检查、smoke／ConfigWatcher／Supply／Scan 四套测试、EWC API 契约门），逐项 `VERIFY: PASS`。**本版未装机、未打包、未上传、未发布，也未做任何实机复核**——上面的数字都来自日志/归档与托管测试，不是实机截图。

## 1.19.57

- **A（review 1）：装饰块的「是同一个节点」比较终于可能为真。** 1.19.56 的 `InsideDecorationBlock` 沿祖先链走，拿每一层 `transform.TryCast<Component>()` 的指针直接和 `m_artifactInfo_text`／`m_ArtifactInventoryDisplay` 等原生字段比——同一 GameObject 上的文字组件、显示组件与 Transform 是三个不同的原生对象，这个比较**永远**为假，于是没有任何节点被判为「在装饰块里」，分类器的 `Visual` 分支形同不存在。现在 `SameNode` 把双方对齐到同一个锚点：先比 `transform.Pointer`，再比 `gameObject.Pointer`；块身份不再读 `_page`／`_succeeded` 缓存（`ResetPlacement` 会在扫描与隐藏的同一帧把它清空），而是由调用方把**活页面**传进来，扫描用页面自己的类型判成功/失败页。哪一块算装饰还由玩家三个开关决定（新增 `ResultVanillaBlockPolicy.IsDecoration`）：只有本模组**真要移走**的块才是装饰块；玩家要求可见的块（`ShowSuccessArtifacts`／`ShowSuccessPlayerReports` 打开、`HideVanillaFailBlocks` 关闭）留在分类器之外，保持 1.19.54 的 fail-safe（其 `active` 的 `CM_Item` 仍是墙），板子绕开玩家要看的东西。绘制路径取页面也改成 `LivePage`（`_page` 为空时回落到活着的成功/失败页），F8 关闭后照旧不画。

- **D（早板，review 3）：同一页的早板不再被每次 retry 清掉。** `Refresh` 过去对同一页的每一次 retry 都先 `ResetPlacement()` + `RestoreHidden()`，把正在显示的 `_grid`／`_content`／`_placed` 与滚轮用的 plate 一起清空：页面一直拿不出成熟板需要的真实信息时，表在 retry 节奏上反复消失再重画，任何一次重测被拒就只剩原版页。现在 `ResultEarlyBoardPolicy.KeepsStanding`（生产函数，`EarlyBoardStanding` 读页面自己的对象）判定「早板仍站在**同一页**上、本帧还没有成熟信息」时**不清、不 restore**；测量仍在同一节奏上跑，成熟时由同一次 `Fit` 一次性覆盖并清 `_earlyBoard`，日志每页一行 `early-board-kept` 说明为什么保留。换了页面（同一页对象被下一局复用，按落位记录的指针判）照旧从头开始；F8/开关关闭时照旧立即不画并复位。

- **量不到装备列时，面板改落在窗口右侧。** 以前这种情况把表格画在**屏幕左边缘**（实测那一帧是 2560×1440 上的 `(24,526)`），离它本该对齐的装备列有一千八百多像素，等于把表格挪到了屏幕另一边。现在所有保守候选都右对齐到窗口自己的右边距，跟自动锚定的正式落位保持同一条边；表格宽度随内容变化时（实测 459 / 479 / 471 / 482 px）只动左边缘，右边不动。检查仍然只有一条：不压住**本帧真的量到**的行，没读到的那几行不声称已避开，覆盖面积照旧打印在日志里。
- **这类「量不到」的诊断不再刷 Warning。** 自动锚点还没量到、装备列只读到一部分、没有可用落点、保守落位、以及唯一那种「表格比窗口还大所以画不下」的情形都改成 `[Info]`；读取真的抛异常时仍是 Warning 并带上异常消息。日志级别没有整体下调，重试、恢复与真实出错的诊断都保留。
- **同一处缺失只写一行。** 以前同一件「量不到」会跟着表宽、落点坐标、窗口尺寸、重试次数的变化反复打印（记录里同一件事写了四行）；现在按语义去重：同一个原因每轮只写一次，只有新的关卡、配置重载或分辨率变化才重新算一轮。恢复成自动落位时仍有它自己的那一行。
- **F8 不再重复打印「原版块原地不动」这类说明。** 结算页上描述页面本身的诊断（例如 `artifact summary` 这一块带着可按控件，所以不隐藏），以前每按一次 F8 就再写一遍（同一句 268 B 写了 14 次、3,766 B）；现在每页只写一次。F8 的显隐回执、布局和点击行为没有改动。
- **版本号回到真实。** 本地载体此前是「1.19.40 标签、1.19.48 行为」的构建，无法区分两次不同的修复；1.19.49 起 `PluginInfo`、程序集/文件版本、Loader 加载行、结算存档里的 `version` 与 Thunderstore manifest 全部同号。
- 以上不改变评分权重与公式、表格行列、局内统计口径、补给归属计数与同步协议字段；`AnchorToFlashlight=false` 的手动落位仍完全按配置，不看这些保守候选。

## 1.19.40

- **结算板可以自己定死字号和位置（新功能）。** 打开 `[Results] FixedLayout` 后，用 `FixedFontPixels` 给**实际屏幕像素**字号（`1`–`240`，写 `5` 就是 5px，小数四舍五入到整数像素），用 `FixedAnchorX` / `FixedAnchorY` 给表格**底边中点**在窗口里的比例位置（左上角是 `(0,0)`，X 向右、Y 向下；`0.5 / 0.8` 即水平居中、底边中点落在窗口高度 80% 处）。成功页与失败页共用这组值，不受页面条带、滚轮缩放和位移键影响；开关关着时这几个键一个字节都不读。给的数字不会被悄悄改成别的值：明显不合规（字号不在 `1`–`240`、锚点不在 `0`–`1`、矩形跑出屏幕、该字号量不出表格）就不画板、原版页原样保留，并写一行 `fixed-layout-*` 诊断说明原因。
- **固定模式压到按钮也不再整块消失。** 它每帧做一次真实矩形相交检查（按钮上沿留 6px 净空），压在一个真正可按的控件上时**照样画板**，只是降到 0.55 不透明度减少遮挡；X 错开不算冲突，重叠消失立刻回到 1.0。扫描证据不足时同样画板（0.55），并且**原版块不隐藏**。`F8` 强制出板与配置热重载在固定模式下一样有效：保存配置后下一帧就按新字号/新锚点重排，不用重开页面。
- **客机失败页的下界改用真正量到的那行提示文字。** 那行不可点击的「等待厅主」提示文字的上沿就是这条带的下界墙，与主机页拿「返回大厅」按钮上沿做下界同一性质；页面自带的固定几何只做封顶，不再被当成「量到了墙」。一堵墙都量不到时保留原版页并有界重测，不拿帧数或超时替玩家下结论，`F8` 仍然可以立刻出板。
- **本机把远端队友救起来不再漏记。** 以前这种救援配对不上施救者，于是这一次救援次数丢掉。现在按「被救目标 + 施救者」配对记账，并保留短暂的完成宽限：重复完成不会记两次，施救者中途换人时旧记录也不会抢功。**只影响救援次数的采集归属，评分权重与门禁不变。**
- 以上不改变评分权重与公式、表格行列、局内统计口径、补给归属计数与同步协议字段。

## 1.19.39

- **结算板按真实可见内容定尺。**
  - 成功页在内容测量完整时，取图标与题注的可见底边作上沿；测量不完整时退回容器边。可用条带变高后，字号按同一高度优先搜索重新拟合。
- **原生 BlinkIn 目标逐个记账。** 单个目标中止不再等同整页动画结束；其余目标仍在运行时不提前落板，动画全部完成才按内容边落位。
- **动画无进展时有界兜底。** 停滞按真实秒与游戏自身的 `BlinkDuration` 判定；兜底布局以 `reveal-unobservable` 明确标记后显示并继续重测，不把超时当成动画完成。
- **失败页保护晚到的原生控件。** 未量到页脚墙时不按窗口比例猜条带；量到按钮后板子停在按钮上方；晚到的控件仍会触发撤板重测。
- **装备名清理。** 按 24 字节同步容量截断后残留的富文本片段（如尾部 `<`、`</c`）只在可证明开标签或容量截断时清理，普通含 `<` 的名字原样保留。
- **联机诊断有界。** 每个队友每类事件的首次、状态变化与异常都保留；重复的接收诊断按计数合并，并在结算前输出汇总；异常文本按桶计数，保留首例与总数。
- 以上不改变评分权重、表格行列、局内统计口径、补给归属计数与同步协议字段。

## 1.19.38

- **结算板第一次出现就是最终位置和大小。**
  - 成功页：等原生分区图标动画（BlinkIn）真正播完再首次落位，用的是游戏自己的协程完成信号，不是帧数或透明度近似；板子上边界改为「图标容器底边」与「真正画出来的图标/题注像素底边」取更深者，所以「主要／精英」那行题注不再被板子压住。
  - 失败页（客机）：不再把「连续两帧什么都没扫到」当成页面已经定稿。只有真的量到可交互控件才按严格路径落位；一直量不到时，在既有 60 次拒收预算之后用同一套几何兜底出板，并在日志里明写这是 fail-open，而不是声称页面已定稿。
  - 超时兜底也不再绕过原生动画门；只有账本已不可能完成或玩家按 F8 时才立即出板，并记一条 `reveal-unobservable`。
- **补给分项次数按「被谁消耗」记账。** 弹药包/工具包/血包落在接收并消耗该包的那一行（含机器人）；补给效率仍按给予者统计。医疗包的种类由治疗包自身的来源判定，不再因为本机追踪范围被降级成「未知」。
- **联机探测有界。** 对未证明安装本模组的队友，每局最多 3 个问候包（两条兼容通道合计 3 个物理包），之后静默，直到对方主动发来数据、换局或换座位；行数据只发给已证明或白名单内的队友。
- **日志收敛。** 结算就绪门、失败页 pending、reveal 未就绪、账本跳过目标等诊断都改为每页只写一次，不再有逐帧重复行。

## 1.19.37

- **本机玩家自己的失血恒为 0。** 伤害底座的补丁只挂在基类上，而玩家身上的实际类型是子类 `Dam_PlayerDamageLocal`，它对基类的 `Receive*` 全部做了 override，于是基类上的 detour 在本机永远不执行。改为按「基类 + 本机子类」两个声明来源分别挂载，并按方法本身去重，同一水位不会被记两次。
- **主机失败页被自己的量测撤板。** 主机失败页上全部控件都是 inactive 时，「页脚按钮本帧被量到」是唯一的严格放行证明，于是页面自己量出的条带被 `no-footer-unproofed` 撤回，只能靠 F8。改为把这一形状写成策略：没有 active 且与板重叠的控件、扫描完整、上界来自本页标题锚点且下界来自本页量到的文字/控件，就允许按页面自己的条带落板；真的被控件压住仍然 defer。

## 1.19.36

- **失血少记第一刀。** 水位原本只对「先有水位、随后下降」的读数记分，而某个底座在本机第一次被看见时看到的往往正是命中它的那一刀。改为在伤害入口前缀里用游戏自己的 `Health` / `HealthMax` 播种水位。
