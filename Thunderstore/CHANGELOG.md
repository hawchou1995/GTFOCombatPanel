# Changelog

## 1.19.38

- **结算板第一次出现就是最终位置和大小。**
  - 成功页：等原生分区图标动画（BlinkIn）真正播完再首次落位，用的是游戏自己的协程完成信号，不是帧数或透明度近似；板子上边界改为「图标容器底边」与「真正画出来的图标/题注像素底边」取更深者，所以「主要／精英」那行题注不再被板子压住。
  - 失败页（客机）：不再把「连续两帧什么都没扫到」当成页面已经定稿。只有真的量到可交互控件才按严格路径落位；一直量不到时，在既有 60 次拒收预算之后用同一套几何兜底出板，并在日志里明写这是 fail-open，而不是声称页面已定稿。
  - 超时兜底也不再绕过原生动画门；只有账本已不可能完成或玩家按 F8 时才立即出板，并记一条 `reveal-unobservable`。
- **补给分项次数按「被谁消耗」记账。** 弹药包/工具包/血包落在接收并消耗该包的那一行（含机器人）；补给效率仍按给予者统计。医疗包的种类由治疗包自身的来源判定，不再因为本机追踪范围被降级成「未知」。
- **联机探测有界。** 对未证明安装本模组的队友，每局最多 3 个问候包（两条兼容通道合计 3 个物理包），之后静默，直到对方主动发来数据、换局或换座位；行数据只发给已证明或白名单内的队友。
- **日志收敛。** 结算就绪门、失败页 pending、reveal 未就绪、账本跳过目标等诊断都改为每页只写一次，不再有逐帧重复行。

## 1.19.37

- **本机玩家自己的失血恒为 0。** 伤害底座的补丁只挂在基类上，而玩家身上的实际类型是子类 `Dam_PlayerDamageLocal`，它对基类的 `Receive*` 全部做了 override，于是基类上的 detour 在本机永远不执行。改为按「基类 + 本机子类」两个声明来源分别挂载，并按方法本身去重，同一水位不会被记两次。
- **主机失败页被自己的量测撤板。** 主机失败页上全部控件都是 inactive 时，「页脚按钮本帧被量到」是唯一的严格放行证明，于是页面自己量出的条带被 `no-footer-unproofed` 撤回，只能靠 F8。改为把这一形状写成策略：没有 active 且与板重叠的控件、扫描完整、上界来自本页标题锚点且下界来自本页量到的文字/控件，就允许按页面自己的条带落板；真的被控件压住仍然 defer。

## 1.19.36

- **失血少记第一刀。** 水位原本只对「先有水位、随后下降」的读数记分，而某个底座在本机第一次被看见时看到的往往正是命中它的那一刀。改为在伤害入口前缀里用游戏自己的 `Health` / `HealthMax` 播种水位。
- **结算补给列改回四格。** `补给效率 / 弹药包 / 工具包 / 血包`，一位玩家一行；三分类真的成立时才打印具体次数，否则第 3、4 格写 `?`，余数为零才写 `0 / 0`。
