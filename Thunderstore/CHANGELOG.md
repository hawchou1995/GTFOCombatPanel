# Changelog

## 1.19.16
- **根因：主机成功页把「送回大厅按钮的上边缘」当成了条带的绝对下界，于是 132px 的条带去装 270px 的硬地板，逐帧静默不画**：`ResultsDisplay.SuccessRegion` 的主机分支（`ResultsDisplay.cs` 的 `else` 分支，`area = ResultsRegion.Resolve(completionMeasured, completion, true, buttonTop, …)`）把条带下界取成 `buttonTop - MessageGap`，`Placement` 再把玩家配置的纵向偏移加到上界，得到真实一局里的 `strip=(538..670)`（132px）。而 `HudTable.BuildGrid` 的可读性地板不允许结算板再小：`FitBoard` 在按钮高度不可读（该局 `lobbyEdge=band`，`buttonHeight=NaN`）时用绝对最小 6px 字号，30 行 × 9px = **270px**。`Fit` 的 `ResultBoardHold.TryPlace` 因此每帧返回 false，只打一条 `[DIAG] result board cannot fit` 就返回，`_placed` 永不置位，`Draw` 什么都不画。日志里 `[DIAG] settlement saved` 与 `[DIAG] influence board … drawn by IMGUI` 的矛盾（前者有、后者 0 次）来自 `Prepare` 里 `ResultsSaver.Save` 在 `Fit` **之前**无条件执行——JSON 落盘从来不等于落板。客机之所以有：客机走 `ResultsGuestPageGeometry` 固定几何（下界 = 屏高 − 8·scale ≈ 1432），完全不看任何按钮，所以只有主机会被按钮顶边夹死。**「不遮挡交互」这条硬约束本身没错，错在把按钮顶边当成了页面的下界，从而放弃了按钮下方 683..1440 之间约 700px 的空白，也错在条带不足时没有任何降级出路。**
- **新行为：按钮矩形变成「必须避让的空档」，板子落到它下方那条自由带里**。新增纯托管策略 `ResultBoardBands`（`LayoutPolicy.cs`）：`TryBelowActions` 把交互扫描真实量到的每个控件矩形按页面自身 gap 外扩后从页面上「挖掉」，在 `[锚点上沿, 屏高−8]` 内取剩余的连续自由区间，跳过那条本来就属于调用方的「锚点起始带」，回答其中最矮高度最大的那条（`ResultBoardBandKind.BelowActions`）。页面上真正决定用不用它的是新增的显式角色策略 `ResultPageRolePolicy`（`ResultVisibility.cs`）：`UsesBandBelowActions(role, stripHeight, floorHeight, bandHeight)` 只在**主机** + 条带确实短于板子自身地板 + 自由带确实装得下地板时返回 true。地板值由 `ResultsFontGrowth.MinimumBoardHeight(rows, rowEm, density)` 给出（30 行 × 最小的 6px 字号行高，与日志里的 270px 逐像素一致）。真实那一局：按钮矩形 683 起、自由带为 `(743..1432)` 共 **689px**，板子落在这里，按钮上方 535..667 那段原版内容原样保留（空白带），**没有任何交互控件被覆盖**——自由带按构造就不含任何被量到的控件矩形，逐帧 `ResultInteractionStripPolicy.OverlapsBoard` 仍然对每一个 active 控件做重叠保护。`ResultFooterSource` 新增 `BelowActions` 记录这条落位的来源，逐帧 `BoardStillSafe` 只在来源不是这条带时才用「按钮净空线」判定；落在带里的板子不再被记成「靠猜落位」，因此不浪费那一次 `ResultAnchorRecovery` 二次测量。`ResultBoardHold.TryPlace` 依旧拒绝比带子更高的板子，`bottomAligned: false`（上界悬挂）、`ResultsUpperBound.Decide` 的延迟落位、按钮缺失时的 fail-closed 全部未变。
- **主机不再比客机更差，也不再被灌输客机的语义**：`SNet.IsMaster` 的读取收口到 `ResultsDisplay.Role()`（只有两处读取：角色助手与扫描自身的覆盖边），`GuestClient()` 变成 `ResultPageRolePolicy.IsClient(Role())`。`ResultNoFooterGate` 依旧是客机专属证明（`ResultPageRolePolicy.UsesNoFooterSafeArea`），但主机不再被迫依赖它：主机有「按钮可测 → 条带/自由带」与「按钮不可测 → 原版保留」两条显式结果。原先给主机打印的「the guest safe-area proof is incomplete」已删除，改为按角色如实描述（`role=host|client`、`noFooterProof=available|not-this-role`、`count/unmeasurable/complete/nativeVisible/footerTop/need=`）。
- **日志说真话**：`[DIAG] success region` 末尾那句「drawn, or laid out and still revealing…」被删掉——它只在量到条带时打印，却读起来像「板子已经在屏上」。现在这行只陈述量到了什么（`anchorSource`、`completion`、`lobbyButton`、`lobbyEdge`、`boardTop`、`room`、新增 `boardBand=`、`boardFloor=`、`role=`），是否落板由 fit 自己那行负责。`[DIAG] result board cannot fit` 现在带 `role=`、`page=`、`strip=…px`、`grid=…`、`need=…px`、`have=…px`、`footerSource=`、`buttonTop=`、`screen=`；新增 `[DIAG] success strip cannot hold the board's own floor`（条带不足、改走自由带，含条带/带子/按钮的真实像素）与 `[DIAG] success board deferred`（条带和带子都装不下时的诚实拒绝）。
- **静默拒绝补有界诊断（每页每原因一条，不刷屏）**：新增 `ResultsDisplay.ReportHeldBack(where, reason, detail)`，接入原先不说话的路径——`Draw` 的 `_grid/_content/_page` 空返回（`reason=no-placement|no-live-page`）、失败页持有板的 `TryHold` 失败、`BoardStillSafe` 里成功/失败两页的完成区/标题未就绪、板子落在条带外、板子触到按钮净空线、`HeldGridFits` 拒绝、`Placement` 里 `room <= 0` 与 `grid == null`、`FailureStrip` 的 `titleKnown` 与 `top/bottom` 算术失败；每行都带 `reason=`、`role=`、`need=`、`heldStrip|have=`、`top/bottom`、`detail=`，并且**未落位时不打印假的 0..0 条带**（`heldStrip=none`）。另外 `Mathf.Max(0f, NaN)` 的传播修复为两角色统一：玩家把 `ResultsOffsetY` 手改成 NaN/负值时按 0 处理（原先只有客机做了这件事，主机会得到整条 NaN 条带并静默不出板）。

## 1.19.0
- Weapon damage is now the damage the game actually applied, not the figure the weapon carried into the strike: the armour of the limb that was hit and the precision / weakspot multiplier are included, for bullets, melee, explosives and EWC's delayed, burst and damage-over-time weapons alike. A client whose host runs no panel of its own reads the enemy's health before and after its own blow, so its row no longer reads low against a host that does run one.
- Nothing is put on the wire for a player this machine has no evidence about - a greeting included. A peer is spoken to when its SteamID64 is named in `[Squad Sync] AllowlistedPeers`, or after it has itself sent this machine a packet of this build's protocol; a machine that runs no mod, a bot and a stranger are never handed bytes they have no handler for. Leave the list empty and the panel shares only with players who speak first, so two modded clients behind a host that runs no mod pair up when one of them names the other.
- This build speaks protocol 8. A mixed lobby stays silent on purpose rather than decoding each other's fields, so both machines have to be on 1.19.0 to exchange anything.
- Only the melee and Scout (tentacle) rows carry a sleeping-kill figure, each with its own multiplier (`SleepingMeleeKillMultiplier` / `SleepingScoutKillMultiplier`, default 2, range 1-10). The three weight classes (minor / elite / BOSS) score and display their total only and no longer take a sleeping multiplier; `SleepingKillMultiplier` is kept as the fallback for the two new fields when the file omits them.
- The melee and Scout rows are three columns - total kills, the part landed on a sleeping enemy, and the damage that went into them. The Scout row's damage now travels with the row instead of being counted only on the machine that dealt the blow.
- Every settlement cell uses one separator, ` / `, with the unit or the meaning moved into the row label; `%`, `~` and `—` are unchanged. Settlement columns 2-5 share one width, the widest of them, so the numbers line up down the board.
- The success page's board now runs from the completion section down to the return-to-lobby button the player can actually see: a control the page switched off, faded to zero alpha, or laid out past the window no longer costs the board its height.
- A result page's footer animates in, so the board waits for the button edge to settle before it measures - bounded, so a hover that keeps nudging the edge cannot hold it back for ever.

## 1.18.0
- Settlement titles are JSON-configurable, each with its own description: total damage, minor/elite/BOSS kills, melee and Scout kills. A player takes only a metric they lead the squad in outright, that is enabled, weighted above zero and has real data; the choice is the candidate with the largest actual contribution to the final score, negative metrics by their real severity. A tie or an all-equal squad awards nothing, and no qualifying candidate falls back to the neutral title. The old `ZeroScore` bypass is gone, so a displayed zero no longer overrides the top rule.
- Kill cells gain a sleeping / awake / unknown split of the same count, in the existing cell, with no new metric and no new row. A sleeping kill is worth twice an awake one of the same class by default (`SleepingKillMultiplier`, 1-10). The state is read from the enemy before the killing blow; a state that cannot be read stays unknown and never counts as awake or asleep.
- Supply quality and downs cells now carry this player's own figures: the supply uses whose benefit actually reached that player and how many were ammo packs, and the health actually lost over the run. Giving a pack away is not a use by the giver, a full-health pack with no benefit is not counted, healing never offsets the loss, and a maximum-health change is not a loss.
- Default weights: LoneSurvivor 1.60 and Stagger 1.40, the rest unchanged; thirteen defaults sum to 9.68. Kill tier values stay 0.5 / 1 / 1.5.
- Kill attribution: a death notified before the damage postfix is settled from the health that was actually lost, so a melee killing blow keeps its cause and a second death callback cannot count the same corpse twice. An enemy pooled before its damage component existed no longer carries its predecessor's credited state.
- Sentries: a round is one `FireBullet` scope, and a native `OnBulletFired` raised inside it is that same round; outside every scope the notification is the only evidence and counts. `max(cumulative calls, cumulative events)` is gone, so switching stream or losing one no longer eats rounds.
- Tripmines: reset clears the counted-mine set too, a consumed mine recovered from the field no longer reports a tool recovery, and a tracked placer beats a conflicting detonation core. Glue projectiles credit the owner from `Fire` and reset per pooled projectile, so a reused projectile cannot inherit the previous hit.
- Scans: a taggable list is not a completed scan. A first mark needs the native tagged state or a rising tag timer, bot windows close with their action, and a throttled bot scan keeps the window it actually had.
- Sync is protocol v7 with a 352-byte snapshot: the kill-state split, the self-consumption pair and health lost travel with the row. A kill total and its split are one block and are taken from one machine, so a cell can never print a subset larger than its count. The squad total is held once with the run counter it came from instead of being re-read from whichever cached row was visited last. Older peers are refused by version, not silently half-read.
- Verification: 1514 combat-panel assertions and 9 config-watcher assertions pass on both profiles, Release 0 warnings / 0 errors, and the EWC 4.13.4 API contract is checked against the installed assembly. **No in-game verification this round**: native callbacks, Steam co-op and rendering are not covered by these results, and the reconnect "otherworld" report is not proven or excluded.
## 1.17.31
- Settlement board sizing: the failure and success boards measure the buttons they must clear only when those buttons are actually shown. The failure page keeps an unshown restart control above the lobby button, and reading it cost 143 px of height at 2560x1440; both screens now share the same rule.
- Settlement board keeps a stable size: the first placement waits for the footer to stop moving, so the table is measured once against the settled page and never resizes on a redraw or F5/F8 toggle.
- Column spacing tightened (0.625em to 0.436em between neighbouring columns); rows are at least as tall as the font's own line, so glyphs are no longer clipped top and bottom.
- Sentry hits no longer collapse to one: the turret reports damageSearchID = 0 for a whole run, and keying on it recorded 33 shots as 1 hit. A zero id now counts each recorded damage event; a real id still deduplicates.
- Player titles: a reverse metric (friendly fire, downs) never becomes a consolation title, and only the squad's outright worst earns it. Friendly-fire title is now "敌我不分"; the neutral fallback is "平平无奇".
- EWC projectile weapons (涡轮电浆枪): hits were lost in 1.17.18 because the whole EWC bridge was compiled out of the shared DLL. A dependency-free runtime bridge now binds ExtraWeaponCustomization's public spawn/hit/post-hit/destroy events by name; original owner and weapon are frozen at spawn, and weakspots come from the actual limb.
- Tripmines: a bot's deployer exposes no first-person face, so every bot mine was refused and the deployment column read zero. Mines are now attributed by gear category, and a carried-in (consumed) mine credits its placer's damage without touching deployment or trigger counts.
- Melee kills: the kill cause came from whatever last touched the enemy, so a console kill or a recycled pointer could report dozens of melee kills against zero melee damage. Only the blow that emptied the health bar names the cause now.
- Verification: 1279 combat-panel assertions and 9 config-watcher assertions pass on both test profiles, Release 0 warnings/errors, and the EWC 4.13.4 API contract is checked against the installed assembly. Live gameplay on success screens and in multiplayer is still unverified.
